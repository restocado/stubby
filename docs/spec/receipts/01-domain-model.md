# Domain Model

**Status:** Built  
**Location:** `Domain/Receipts/`: `Receipt`, `FieldRecord`, `ReceiptStatus`, `ReceiptCategory`, `FieldName`.  
**Depends on:** nothing.

## Scope

Entities and the rules that keep them valid. Slices call methods, never set properties directly.

## Behavior

Enums: `ReceiptStatus` (Queued, Processing, Failed, ForReview, Approved), `ReceiptCategory` (the eight fixed categories), `FieldName` (Merchant, Date, Total). Properties match the `Receipts` table in the database design. Subtotal and tax are not stored. `TransactionNo` (`long`) is generated by the database on insert, is read-only in the domain, and never changes. It is not copied to `FieldRecord`. `TransactionNumber.Format(long)` returns the display form: `TXN-` plus the number padded to six digits (`42` → `TXN-000042`, `1000000` → `TXN-1000000`). It is the only place the format is built.

Each transition is a method that throws if the status does not allow it:

| Method | From | To | Also |
|---|---|---|---|
| `Create` | none | Queued | `AttemptsUsed = 0` |
| `StartProcessing` | Queued | Processing | |
| `CompleteExtraction` | Processing | ForReview | stores extracted fields, flag, model, prompt version |
| `FailAttempt(error, max)` | Processing | Queued if `AttemptsUsed + 1 < max`, else Failed | `AttemptsUsed + 1`, `LastError` |
| `ReturnToQueue` | Processing | Queued | `AttemptsUsed` unchanged |
| `Reprocess` | Failed | Queued | `AttemptsUsed = 0`, clear `LastError` |
| `Approve` | ForReview or Failed | Approved | sets final fields, `ApprovedAt`, `IsManualEntry` (true if Failed); returns 3 `FieldRecord`s |

Approved receipts accept no method. Only deletion removes them (NFR-R4).

`CanBeOpened`: ForReview, Failed. `CanBeDeleted`: all but Queued and Processing.

`FieldRecord` is immutable, has no receipt reference, and is built only by `Approve`. From ForReview: extracted value from the receipt (null if none), `IsManual = false`, model and prompt version copied. From Failed: extracted value, model and prompt version null, `IsManual = true`. Dates are `yyyy-MM-dd`, totals have two decimals, invariant culture.

## Acceptance criteria

- A new receipt is Queued with `AttemptsUsed = 0`.
- `TransactionNo` has no public setter, and no method changes it, including `Reprocess`.
- `Format(1)` is `TXN-000001`, `Format(42)` is `TXN-000042`, `Format(999999)` is `TXN-999999`, `Format(1000000)` is `TXN-1000000`.
- With max 1, `FailAttempt` sets Failed. With max 3, the first two calls requeue and the third sets Failed.
- `ReturnToQueue` leaves `AttemptsUsed` unchanged.
- `Reprocess` on Failed resets attempts and error. On any other status it throws.
- `Approve` on ForReview returns exactly 3 records, including unchanged fields.
- `Approve` on Failed returns 3 records with `IsManual = true` and sets `IsManualEntry`.
- `Approve` throws on Queued, Processing or Approved, and when merchant is blank, date is missing or category is undefined.
- Every method on an Approved receipt throws.
